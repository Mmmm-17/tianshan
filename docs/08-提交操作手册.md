# 一、中期考核提交内容清单

中期考核总分 100，由三个板块按 **4 : 3 : 3** 加权：

| 板块 | 权重 | 提交形式 | 归口 |
|---|---|---|---|
| **① 指标考核（完成度）** | **40%** | 视频（`.mp4`，打包为 `.zip`） | 邮件附件 |
| **② 规则测评** | **30%** | 线上答题（80 题，1 次机会） | 系统内完成 |
| **③ 文档评估** | **30%** | Markdown 文档，放 GitHub/Gitee 仓库 | 邮件正文附链接 |

## 1.1 材料一：指标视频包（占 40%）

### 技术要求（手册硬性规定）

| 项 | 要求 |
|---|---|
| 格式 | **`.mp4`** |
| 清晰度 | **不低于 1080p** |
| 帧率 | **不低于 30 帧/秒** |
| 压缩包名 | **`陵龙战队 天山战队 毛诗棋.zip`**（实训战队名 + 队伍名 + 队长名） |
| 内部组织 | 一条指标一个视频文件，文件名含指标编号 |

### ⚠️ 短视频四条铁律（违反任一条 = 该指标**不予计分**）

> 摘自手册 P9，是最容易被扣分的地方：

| # | 铁律 | 说明 |
|---|---|---|
| **①** | **不同时展示其他指标** | 一个视频只演示一个指标，画面里不能同时出现别的可得分动作 |
| **②** | **不展示未通过的指标** | 做不到的动作不要拍进去，哪怕只是"顺便经过" |
| **③** | **不能剪接** | 一镜到底，禁止任何形式的剪辑拼接 |
| **④** | **必须有参数标识和实测数据** | 画面里要能看见尺寸、数值、刻度 |

### 拍摄规范（本队自定，便于评审定位）

```
每条视频开头报一句："天山战队，第 X 项，XXX"
时长控制在 20~40 秒
```

### 指标自查表（拍摄时逐条勾）

| # | 指标 | 演示要点 | 拍了 | 过了 |
|---|---|---|---|---|
| 1 | 外形展示 | 绕车一周，整车完整入镜 | ☐ | ☐ |
| 2 | 电机运动（全部） | 四轮正反转各演示一次 | ☐ | ☐ |
| 3 | 舵机运动（多项） | 6 路依次动作 | ☐ | ☐ |
| 4 | 舵机保持 | 停在**非初始位置**保持静止 5 秒 | ☐ | ☐ |
| 5 | 底盘运动（全部） | PS2 手柄与车体**同框**，演示前后/横移/旋转 | ☐ | ☐ |
| 6 | 尺寸规范 | 直尺实测长宽高，数字拍近景 | ☐ | ☐ |
| 7 | 方块携带（单一） | 地面抓取、携带移动 | ☐ | ☐ |
| 8 | 方块携带（多项） | 保持一个的同时再抓第二个 | ☐ | ☐ |
| 9 | 结构稳定性 | 直尺量 180mm，底面朝下自由落体 | ☐ | ☐ |
| 10 | 规划/采购单 | 见仓库 `docs/` 采购清单 | ☐ | ☐ |
| 11 | 全程演示 | 从起点抓块走完全程，中途不落地 | ☐ | ☐ |

> **完整 43 项指标见手册 4.1 节**（`D:\天山\5-场地与规则图\` 与手册原文）。上表为本队主攻项目，其余按实际完成情况补录。

### ✅ 一条重要豁免条款

> **手册 P11：「基于当前成本核算规范与时间安排，允许中期测评队伍不产出实物演示。」**

**意思是：即使车没跑起来，只要文档和测评做好，仍可参与排名。**
本队若实物未达标，仍应提交视频包（哪怕只覆盖已完成的少数指标），不要让材料整包缺失。

## 1.3 材料三：文档评估（占 30%）

### 格式硬性要求（手册 P10）

| 项 | 要求 | 我们的状态 |
|---|---|---|
| **文件格式** | **Markdown（`.md`）** | ⚠️ **原为 .docx，已转换** |
| 内容组织 | **按设计进度完成时间从早到晚** | ✅ |
| 板块结构 | **以单个机器人功能为一个板块**，`H2 标题 = 具体功能` + 正文 = 功能描述与开发历程 | ✅ |
| 文档数量 | 每篇由若干个上述板块组成，可有多篇 | ✅ 7 篇 |
| 开源声明 | 使用了开源项目的，**在文档末尾完整说明** | ✅ 见每篇末章 |

### 仓库规范（手册 P10）

| 项 | 要求 | 我们的状态 |
|---|---|---|
| **仓库名** | **队伍名称的英文或拼音** | ✅ `tianshan` |
| **文档位置** | 仓库根目录下名为 **`docs`** 的文件夹 | ✅ `docs/` |
| 其他部分 | 不作额外要求 | — |

### 评估等级标准（对着改，别对着猜）

| 等级 | 标准 | 我们要做到的 |
|---|---|---|
| **5 分（卓越）** | 内容详尽、逻辑透彻、技术有深度；**完整记录从构思到实现的全部过程**；不仅写"做了什么"，更写**"为什么这样做"**（技术选型对比、难点与解决方案、迭代优化过程），体现独立思考 | 六版方案对比表、上电乱转三天半复盘、每条改动写清"触发问题 → 决策依据 → 代价" |
| **4 分（优秀）** | 内容详尽、逻辑清晰、技术实现完整；涵盖所有关键环节；准确描述实现方案和最终代码 | 各功能皆有实现细节与代码片段 |
| **3 分（良好）** | 内容完整、思路基本清晰；细节或有缺失 | — |
| **2 分（合格）** | 记录过程但有遗漏，逻辑有不连贯 | — |
| **1 分（通过）** | 按规定提交但内容不完整 | — |

> **冲刺 5 分的关键**：把"为什么否掉前一个方案"写清楚。评审看的是**决策链**，不是最终结果。

# 二、GitHub 仓库的创建方式

## 2.1 创建仓库（网页操作，5 分钟）

### 第 1 步：登录 GitHub

```
https://github.com
没有账号先注册（用邮箱注册即可，免费）
```

### 第 2 步：新建仓库

```
① 点右上角 "+" → "New repository"
② Repository name 填：  tianshan
   （⚠️ 必须是队伍名拼音/英文，不能叫 tianshan-team、TS-1 之类）
③ Description 填：  天山战队 CRTC2026 中期考核文档
④ 可见性选：  ☑ Public（公开）
   （Private 评审看不到，会被判为未提交）
⑤ 勾选 "Add a README file"
⑥ 点 "Create repository"
```

### 第 3 步：确认仓库名与可见性

```
✅ 仓库地址形如： https://github.com/Mmmm-17/tianshan
✅ 页面顶部显示 Public
```

---

## 2.2 上传文档（两种方式，任选）

### 方式 A：网页拖拽（最简单，推荐）

```
① 进入仓库 → Add file → Upload files
② 把 7 个 .md 文件拖进去
③ 点 Commit changes
④ 再点 Add file → Create new file
   文件名填： docs/README.md
   内容随便写一句占位，点 Commit
⑤ 然后把其余 .md 文件也移进 docs/：
   逐个文件点进去 → 铅笔图标（编辑）→ 在文件名前加 "docs/" → Commit
```

**⚠️ 更省事的做法**：直接建 `docs` 文件夹再传：

```
① 仓库页 → Add file → Create new file
② 文件名填： docs/README.md
   （GitHub 会自动创建 docs 文件夹）
③ 提交后进入 docs 文件夹 → Add file → Upload files → 拖入其余 .md
```

### 方式 B：Git 命令行（会用的话更快）

```bash
# 1. 克隆仓库
git clone https://github.com/Mmmm-17/tianshan.git
cd tianshan

# 2. 建 docs 目录，拷入文档
mkdir docs
copy "D:\天山\★A-中期考核提交\1-文档仓库docs（对应 GitHub docs目录）\docs\*.md" docs\

# 3. 提交推送
git add docs/
git commit -m "中期考核文档：技术文档 + 开发日志 + 成员成长史 x4 + 提交手册"
git push origin main
```

## 2.4 常见错误自查

| ❌ 错误 | 后果 | 正确做法 |
|---|---|---|
| 仓库设为 **Private** | 评审打不开 → 视为未提交 | 必须是 **Public** |
| 仓库名用了 `tianshan-team` / `TS-1` | 不符合"队伍名拼音"规范 | 就叫 **`tianshan`** |
| 文档放在根目录，没有 `docs/` | 不符合仓库规范 | 全部放进 **`docs/`** |
| 仍提交 `.docx` / `.pdf` | 不符合"必须 .md" | 转成 **`.md`** |
| 只传了技术文档，没有成员日志 | 文档不完整，评级下降 | 7 篇齐全 |
| 没有开源声明 | 5 分无望 | 末尾必须有声明章节 |
